# Project shape after `sk:install`

> Reference detail for the `lvntr-starter-kit` skill — read on demand.

Since v13.6.0 the kit is **vendor-first**: most module runtimes (Actions, DTOs,
Queries, Events, Listeners, Services), kit middleware, kit migrations, kit
translations, and the composables run **from the vendor package** and resolve
through `class_alias` / local-first resolvers. Your app owns the HTTP layer,
Models, Policies, routes, Vue pages, and config. A local copy always wins over
the vendor one (alias-skip / local-first invariant).

```
app/
├── Domain/
│   ├── Auth/                                               # app-owned auth actions
│   ├── User/ , Role/                                       # auto-ejected on fresh install (app-owned)
│   └── {YourEntity}/{Actions,DTOs,Queries,Events,Listeners} # your business logic
│       # Other kit domains (Setting, ActivityLog, Logs, Session, Media, ApiClient,
│       # ApiRoute, FileManager, Shared) run FROM VENDOR — take ownership with sk:eject.
├── Enums/{PermissionEnum,RoleEnum,…}.php                   # PermissionEnum is regenerated by sk:update
├── Http/
│   ├── Controllers/{Admin,Api,Service}/…Controller.php     # thin controllers (app-owned)
│   ├── Requests/{Admin,Api}/{Entity}/…Request.php          # FormRequests
│   ├── Resources/{Admin,Api}/{Entity}/{Entity}Resource.php
│   ├── Middleware/{HandleInertiaRequests,EnsurePasswordNotExpired,CheckApiDocsAccess}.php
│   │   # CheckResourcePermission, SecurityHeaders, AssignTraceId, SetLocale,
│   │   # ValidateTurnstile run from vendor (App\ names resolve via class_alias)
│   └── Responses/DatatableQueryBuilder.php                 # thin App\ shim over the vendor class
│       # ApiResponse / ApiException / sk-helpers run from vendor — no app copy
├── Models/                                                 # Eloquent models (always app-owned)
└── Providers/DomainServiceProvider.php                     # wire YOUR events/listeners here

config/
├── starter-kit.php            # published — editable (passport TTLs, run_migrations, …)
├── permission-resources.php   # YOU edit; declares resources — NEVER overwritten by sk:update
└── settings.php               # settings panel groups + sensitive keys — NEVER overwritten
    # activitylog / inertia / media-library configs are no longer published;
    # the kit sets its required keys at runtime. Publish the upstream package's
    # own config tag if you need full control.

routes/
├── web.php / api.php          # orchestrators (require children)
├── web/{entity}-route.php     # one file per resource
└── api/{entity}-route.php

resources/
├── js/
│   ├── components/Lvntr-Starter-Kit/   # ONLY exists if sk:publish ran (local copy wins)
│   ├── composables/                    # index.ts + useAdminMenu local;
│   │                                   # the 15 kit composables resolve local-first → vendor
│   ├── layouts/{AppShell,AdminLayout}.vue
│   ├── pages/Admin/**                  # your Vue pages
│   ├── plugins/                        # v-can / v-role resolve local-first → vendor
│   └── theme/                          # custom-theme preset override (VITE_SK_THEME=custom)
└── css/theme/                          # slot-based theme tree; main/ = base theme
    └── _active.css                     # GENERATED by the skTheme() vite plugin — never edit

lang/
├── en/validation.php , tr/validation.php   # app-owned (framework override surface)
└── …                                       # 44 sk-*.php files run from vendor with
                                            # precompiled JSON; app lang keys win per key
                                            # (publish with sk:publish --tag=lang to customize)

.claude/skills/  + .codex/skills/       # kit AI skills for Claude AND Codex
                                        # (.codex is a generated mirror of .claude)
storage/starter-kit/hashes.json         # sk:update tracking — auto-managed
storage/starter-kit/install-progress.json  # sk:install checkpoint (enables --resume)
```

Kit migrations (media, activity_log, definitions, settings, …) are
vendor-loaded when `config('starter-kit.run_migrations')` is `true`; publish
`--tag=starter-kit-migrations` and disable the flag to take control.

The package source is at `vendor/lvntr/laravel-starter-kit/{src,stubs,config}` —
read it if you want to understand internals, but never edit it.
